## 8. 设计可靠性评估

| 组件 | 评估 | 风险与缓解 |

## 9. 已识别的范围外风险与主动裁剪

| 风险 | 为何可能超范围 | 裁剪决策 |
|------|----------------|----------|
| 42 卷全部跑完 AI 注释 | Flash 调用量大、费用高、review 时间长、质量参差不齐 | V0.1 只跑 fixture + 少量代表性 passage；其余留 V0.2 |
| 通用胡三省注 importer | 计划书 §4.2 已说明只 fixture；通用 parser 需要大量边界处理 | 严格保持 fixture 级别，V0.2 再通用化 |
| 跨 passage / 跨卷文本选择 | 计划书 §3.2 已限制单 passage；实现跨段会引入 interval composition | V0.1 完全禁止跨段选择 |
| 任意重叠高亮 composition | 计划书 §8 已明确不做 | 新标记与已有 user annotation 重叠即阻止 |
| 人名/地名跨卷实体统一库 | 需要复杂的实体消歧与持久化 | V0.1 仅做当前 passage / reading unit 内解析；同名由 reviewer 控制 |
| 手机/平板深度适配 | 需要单独交互设计 | 响应式仅保证桌面浏览器，移动端不深挖 |
| Obsidian / 第三方导出 | 不在 V0.1 范围 | 完全不做 |
| 全文搜索 | 需要索引与大量 UI | 完全不做 |

## 10. 建议的最多 5 项删减（如时间吃紧）

   若评分实现耗时，可先保留 `overall` + `unsupported_claim_risk`，其余维度留 V0.2。

   不删除测试文件，只减少参数矩阵；保证每条关键行为至少有一个测试即可。
