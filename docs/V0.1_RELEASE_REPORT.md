## 4. 已知限制

**功能范围（计划书明确裁剪）**
- 仅 vol01 有 AI 注释；其余 41 卷只有正文。
- 古注只有 2 条 fixture，无通用胡注 importer。
- 个人标记限单段落内；与已有标记重叠时阻止创建。
- 无导出、无云同步、无全文搜索、无账号。
- 响应式只保证桌面浏览器。

**实现层面的限制**
1. **IndexedDB 持久化只测了 reload**，未自动化「关闭浏览器再打开」。两者对 Dexie 而言路径相同，但没有独立验证。
2. **`review_annotations.py` 的报告是「本次运行范围」聚合**：只跑单个 passage 会用 1 段的结果覆盖整卷报告。需按卷重跑才能得到完整报告（本次已重跑恢复）。
3. **竖排只做到了可用，不是排版优化**：切换模式会保留当前 passage，但不保证像素级位置。
4. **阅读位置不持久化**：刷新回到当前卷开头（只存主题/横竖排/字号/行距/面板状态）。
5. **anchor 只在渲染时校验并跳过**：corpus 漂移后失效的标记不会显示，但也不会通知用户（仅 console.warn）。
6. **`build_catalog` 发布 works/ 时存在极短的窗口**：`rmtree` + `rename` 之间 works/ 会短暂不存在，且 works/ 先于 catalog.json 发布。本地发布流程可接受，并发静态托管可能出现瞬时 404。
7. **`build_catalog` 的 staging 目录位于 `public/` 内**：`public/data.tmp.<hex>` 在进程被硬杀（SIGKILL，非 Python 异常）时会残留，随后被 `vite build` 拷入 `dist/`。窗口极窄、仅影响本地构建；正常异常路径由 `finally` 清理，不阻塞 tag。
8. **正文按字面保留 Wikisource 编辑标记与合字占位**：canonical 中有 3 处 `[…]` 编辑夹注（如 `[秋七月]`）与 6 处 `{…}` 合字占位（如 `{世疐}`、`{艹兔}`，共 vol05/vol15/vol17/vol24/vol25 等），阅读时原样显示。这是刻意的：规则 9 禁止静默改写原文，故只记录不改写；若要替换应作为 V0.2 的显示层处理并单独报告来源。
7. **jsdom 下测试较慢**（最慢单测 21.4s，`testTimeout` 放宽到 60s）。真实浏览器中同样 19 条 e2e 只需 4.6 秒。

**R02 reviewer 记录的未处理项**（按指示只修 blocker/major，MINOR 保留）
- `<dl>` 无条件并入 canonical，无 provenance 区分（当前 42 卷核对无污染）。
- Wikisource 卷链接发现规则较脆（依赖链接文字「第X卷」与子页路径）。
- `Reader.tsx` 的选择器守卫 `[data-note-popover]` 无元素携带（死选择器）。
- 损坏的 IndexedDB 行只 `console.warn` 后丢弃，用户无感。
- `usePreferences` 的 localStorage JSON 未过 zod 校验。
- 个人标记层不可键盘操作（工具条只在 mouseup 出现）。
- 工具条 mouseup 只挂在 scroller 上，拖选越出窗口松开则不出现。
- fresh clone 需先跑 sync 才能 pytest / Playwright（README 已说明）。

## 5. V0.2 候选（最多 5 项）

1. **补齐 AI 注释覆盖与质量**：扩展到更多卷，并收敛 generator 的类型混淆（官職/泛稱誤畫專名線）——这是 V0.1 观察到的主要质量问题。
2. **通用胡三省注 importer**：把古注从 fixture 升级为可导入的独立层。
3. **阅读位置与状态的完整持久化**：跨会话记住阅读位置、卷内进度。
4. **个人标记增强**：跨段落选择、任意重叠 composition、导出（Obsidian / Markdown）。
5. **移动端 / 平板适配**：当前仅保证桌面。
