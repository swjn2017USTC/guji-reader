# Guji Reader 验收与 V0.2 升级方案

日期：2026-09-22

审查原则：仓库中的旧计划、规则和 Release Report 只作为历史材料；本文件以本轮实际复跑、当前代码和当前 Git 状态为准。

## 1. 结论先行

### 1.1 产品结论

**V0.1 本地阅读 MVP：PASS_WITH_MINOR。**

当前版本已经能稳定完成核心闭环：打开 42 卷正文、切换横排/竖排和主题、显示古注与 AI 注释、创建并持久化个人标记。Python、前端单元测试、类型检查、生产构建以及隔离端口上的 Chromium 端到端测试均通过。

### 1.2 GitHub 发布结论

**公开仓库推送：HOLD；私有仓库推送：完成 G0 后可进行。**

当前没有配置 Git 远端，机器上也没有 `gh` 命令；仓库缺少代码许可证与语料复用说明，缺少 CI，并且跟踪了 `.DS_Store`。此外，当前 Vitest 依赖命中 2 个中危漏洞告警。因此不应把“测试通过”等同于“已经适合公开发布”。

在用户明确 GitHub owner、仓库名和公开/私有可见性之前，不创建远端、不推送、不覆盖远端历史。

### 2.1 关于端到端测试的假失败

按 README 中的 `env -u CI npx playwright test` 首次执行时，大量用例失败。根因不是阅读器回归，而是 5173 端口已运行另一个项目，且 `reuseExistingServer: !process.env.CI` 让 Playwright 直接复用了错误页面。改用 5174 隔离启动后，22 项全部通过。

这说明产品功能通过，但测试入口存在真实的发布工程缺陷：开发机端口冲突可以制造误报，甚至可能制造假通过。G0 必须修复。

### 2.2 本轮没有完成的证据

- 没有完成新的逐屏人工视觉验收；本轮界面自动化覆盖了主要交互和边界位置，但不代替桌面/平板的主观排版验收。
- 没有重跑真实 LLM canary，避免在“只出方案”的阶段消耗接口额度；旧报告中的 canary 结果不作为本轮实时证据。
- 没有验证关闭整个浏览器后 IndexedDB 的跨会话保留；当前 E2E 验证到 reload。
- 没有创建 GitHub 仓库，也没有推送。

## 4. 分项验收

### 4.1 已通过

- **主阅读闭环**：42 卷可加载，正文可读，卷切换、横竖排、主题、字号、行距和专名线开关可用。
- **四层隔离**：canonical、古注、AI 注释、个人标记在数据和渲染层保持区分。
- **注释交互**：AI 注释、古注、个人批注弹层能打开、关闭，并保持单一弹层。
- **个人标记**：高亮/波浪线、颜色、透明度、批注、编辑和删除通过自动化验证。
- **基本韧性**：IndexedDB 失效不会拖垮正文阅读；anchor 会在渲染前校验。
- **构建**：当前数据存在时可产出静态站点。

### 4.2 通过但需修复

- Playwright 默认复用 5173 上任意服务，验收结果不够可信。
- `usePreferences` 读取 localStorage 时未做 schema 校验。
- 损坏的个人标记、漂移的 anchor 只写 console，用户无感。
- 个人标记文本缺少完整键盘操作路径，选择工具条依赖 `mouseup`。
- `<dl>` 导入和卷链接发现规则较脆；目前语料未发现污染，但未来重新抓取有风险。
- AI 质量样本太小：当前质量报告只有 8 段，不能外推到 42 卷。
- 单测明显偏慢，并存在 React 异步更新警告。

### 4.3 GitHub 公开发布前阻塞项

1. **代码与内容许可未拆分声明。** 根目录没有 LICENSE，catalog 的 `license` 为空。代码许可应由项目所有者决定；Wikisource 文本应逐页核对页脚、历史和讨论页，并记录适用许可、来源 URL、抓取时间、修改说明与署名方式。Wikimedia 官方指引提醒复用者核对具体页面许可并履行 attribution/share-alike，而不能只根据“来自 Wikisource”推断。
2. **依赖漏洞未处理。** GitHub Advisory `GHSA-82fw-gwwq-j7x9` 影响 Vitest `>=2.1.0,<4.1.11`，当前为 `3.2.7`；建议定向升级到稳定修复版 `4.1.11`，不要直接执行不可审查的 `npm audit fix --force`。
3. **发布自动化缺失。** 没有 GitHub Actions，远端无法自动证明 60/74/22、typecheck、build 和秘密扫描均通过。
4. **仓库卫生未完成。** `.DS_Store` 已被跟踪且当前修改；应使用 `git rm --cached .DS_Store` 停止跟踪，同时保留 `.gitignore` 规则。
5. **目标远端与权限未知。** 未配置 remote，且本机无 `gh`；需要用户指定 repo 后选择 SSH/HTTPS，不能猜测仓库或强推。

参考：

- [GitHub Advisory GHSA-82fw-gwwq-j7x9](https://github.com/advisories/GHSA-82fw-gwwq-j7x9)
- [Wikimedia Developer App Guidelines：内容许可与署名](https://foundation.wikimedia.org/wiki/Legal:Wikimedia_Developer_App_Guidelines)

## 5. V0.2 分阶段升级计划

每阶段独立提交、独立验收；未过门禁时停止，不把下一阶段混进当前提交。

范围：

1. 由项目所有者选择代码 LICENSE；新增 `NOTICE-DATA.md`，把代码、古籍原文、Wikisource 编辑贡献、AI 注释分别说明。
2. 停止跟踪 `.DS_Store`，检查 `.env`、缓存、构建产物和原始语料均未入 Git。

4. 新增 CI：Python 60、前端 74、typecheck、build、Chromium 22、秘密扫描。
5. 升级 Vitest 至已修复的稳定版本，锁定 lockfile，处理兼容性后全量回归。
6. 修复 React `act(...)` 警告，使测试日志零警告或对必要警告建立白名单。

## 6. 建议的版本目标
